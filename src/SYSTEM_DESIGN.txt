CDS Attend — NYSC CDS Attendance Management System
Comprehensive Frontend Architecture & Project Specification Document
Executive Summary & System Overview
CDS Attend is a modern, web-based management platform built to modernize weekly Community Development Service (CDS) attendance workflows for the National Youth Service Corps (NYSC). The system transitions local government administration away from manual paper registers to a secure, traceable digital ecosystem.

The application serves three primary user tiers:

Local Government Inspectors (LGI): Executive oversight, cross-group auditing, global attendance reports, and administrator moderation.
CDS Group Executives: Session creation, QR code generation, manual check-in overrides, excuse letter reviews, and group member management.
Corps Members: Self-registration, dynamic QR code check-ins, excuse submissions, and individual attendance history tracking.


Technical Stack & Architecture
The application is structured as a decoupled frontend client built with React and Next.js, interfacing with a Python FastAPI backend and PostgreSQL database via a typed RESTful API client.

Core Feature Module Specifications
1. Authentication & Registration Workflow
State Management: JWT token stored securely in httpOnly cookies with client-side context mirror.
Validation Rules:
NYSC State Code format validation (NY/24A/1234 format via regex).
CDS Group selection drop-down linked dynamically to active groups.
Pending Verification Screen: Newly registered members land on an unapproved state blocking dashboard access until a CDS Executive or LGI verifies their profile.
2. Session Management & Dynamic QR Verification
Session Lifecycle: Scheduled -> Active -> Closed -> Archived.
Dynamic QR Codes: Executives launch an active session. The QR generator yields a token that refreshes every 15–30 seconds to prevent dynamic screenshot sharing.
Check-In Validation Engine: Frontend parses payload containing timestamps and geo-fencing coordinates before dispatching the verification payload to /api/v1/attendance/checkin.
3. Attendance Excuses System
Submission Flow: Form supporting reason classification (Medical, Official Duty, Emergency), date picker, and document proof uploading.
Review Interface: Executive split-view panel featuring document preview, approval action buttons, and reason logs.
4. Analytics & Reporting Hub
Metrics Tracked: Attendance rate per CDS group, weekly attendance trends, persistent absent list, excuse approval metrics.
Export Capabilities: One-click CSV and PDF summary report exports powered by structured table outputs.


API Client & Error Handling Architecture
The client uses an Axios-wrapped HTTP module (api-client.ts) integrated with TanStack Query for cache invalidation.// Sample API Error Interface Implementation

export interface APIErrorResponse {

  statusCode: number;

  message: string;

  errorCode: 'UNAUTHORIZED' | 'SESSION_EXPIRED' | 'DUPLICATE_CHECKIN' | 'OUT_OF_BOUNDS';

  details?: Record<string, string[]>;

}

// Global Query Handler Configuration

export const queryConfig = {

  defaultOptions: {

    queries: {

      staleTime: 1000 * 60 * 5, // 5 minutes

      refetchOnWindowFocus: false,

      retry: (failureCount: number, error: any) => {

        if (error?.statusCode === 401 || error?.statusCode === 403) return false;

        return failureCount < 2;

      },

    },

  },

};
